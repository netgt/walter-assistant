# Как пользоваться Walter

Здесь — логика сценариев, подтверждений, вопросов, алертов и роутинга, с примерами.

## 1. Обычный запрос

Пишите как человеку: «покажи последние SMS», «что у меня с деньгами», «прочитай файл отчёт.docx», «открой Telegram».
Walter сам выберет инструмент, получит данные и ответит. Для анализа финансов используется `read_sms`, а не открытие банка.

## 2. Многошаговые планы: разделитель `->`

План — это последовательность шагов, разделённых **`->`** (или `→`). Перенос строки разделителем **не** является.

```
открой openvpn -> подтверди -> собери новости из @markettwits и @telecommunal -> подтверди -> открой openvpn
```

- Каждый `подтверди` — **граница шага**. После выполнения сегмента перед ним Walter показывает карточку «Следующий шаг плана: … Подтверди» и **ждёт вашего ответа**.
- Подтверждением считаются короткие ответы: `да`, `давай`, `ок`, `окей`, `хорошо`, `ага`, `подтверди`, `подтверждаю`, `продолжай`, `готово`, `yes`, `ok`.
- Опечатки прощаются: `подверди`, `подвержд…` тоже распознаются как подтверждение.
- Один смысловой шаг может включать **несколько инструментов** (например `find_files → read_file → write_file`). Подтверждение ставится только после **последнего** действия сегмента, а не после каждого вызова.
- Финальный шаг «открой приложение X» исполняется напрямую.

### Вопрос пользователю внутри плана

Если шаг — «спроси пользователя …», Walter задаёт вопрос и **ждёт свободный текст** (без карточки «Подтверди»). Ваш ответ становится инструкциями текущего сегмента.

```
открой почту -> подтверди -> спроси пользователя имя файла -> прочитай последнюю строку файла -> добавь её в начало файла -> подтверди -> открой почту
```

После вопроса «имя файла?» вы пишете, например, `todo-3` — и Walter читает/правит файл, затем просит подтверждение перед финальным открытием.

### Ожидание ввода

Формулировки «дождись, пока пользователь введёт …» / «подожди …» тоже переводят шаг в режим ожидания вашего текста.

## 3. Оповещения (алерты)

Создаются обычным текстом: «создай оповещение: когда … — сделай …». Каналы: **ПУШ**, **СМС**, **ФОН** (периодическая проверка инструментом).

Пример правила с порогами и памятью:

```
Реагировать только на пуши от Банка, извлекать сумму задолженности;
оповещать при превышении порогов 400000, 500000, … по мере роста;
запоминать пройденные пороги и не оповещать повторно;
записывать состояние в файл и сверяться с ним при каждом запуске.
```

- Состояние хранится в `Download/walter-alerts/alert-<id>.json` (`passed_thresholds`, `last_value`, `processed_events`).
- Walter читает состояние перед оценкой; новый порог сначала **записывается**, и только затем приходит оповещение. Повторные/уже пройденные пороги не дублируются.
- Управление: «покажи оповещения», «выключи <имя>», «измени оповещение …», «удали …».

## 4. Открытие приложений по функции

- Точное имя → `open_app`: «открой Telegram».
- Функция → `open_capability`: «галерея», «переводы», «навигация», «счётчик калорий», «повтор заказа».
  Локальный каталог (`assets/capabilities.json`) сопоставляет функцию с установленным приложением; при нескольких кандидатах Walter спросит, какое открыть; если ничего не найдено — посмотрит список установленных.
- Можно закрепить выбор: «для навигации всегда используй Maps» / «не используй X для этого» — правило сохранится.

## 5. Фильтры событий

- «покажи все уведомления Walter» → только собственные алерты Walter.
- «покажи пуши Альфа-Банк» → только этот источник (источник важнее текста).
- «покажи SMS от банка» → фильтр по отправителю/тексту.
Модель и карточки получают **один и тот же** отфильтрованный набор.

## 6. Поиск по истории

«что я просил сделать с файлом X раньше?» → `search_history` ищет по **всей** сохранённой истории чата и веток, а не только по последним сообщениям.

## 7. Режим лончера

В настройках кнопка **«Сделать лончером»** открывает системный выбор домашнего приложения. Когда Walter выбран лончером:
- обычные системные уведомления скрываются после сохранения в чат;
- собственные алерты приходят только карточкой в чате;
- постоянные (ongoing) уведомления не трогаются;
- кнопка «Открыть» на карточке по-прежнему открывает приложение/чат.

## 8. Меню ввода

В режиме лончера кнопка «плюс» раскрывает вверх **телефон**, **SMS**, **камеру** и **настройки**; повторное нажатие закрывает меню. В обычном приложении справа только кнопка настроек.

## 9. Обучение capability-роутера

- Каталог содержит функции и маршруты к реальным приложениям по пакетам и меткам.
- Запуски через Walter сохраняются локально по package name: количество и время последнего запуска.
- При равных кандидатах приоритет получает чаще используемое приложение; явные `prefer/exclude` правила важнее статистики.
- В настройках прав можно дополнительно включить **«Статистика запусков»**. Тогда учитываются реальные переходы приложений на передний план за 30 дней через `UsageStatsManager`.
- Запросы пользователя не сохраняются в статистике — только package name, count и timestamp.

Матрица реальных intent-filters на IQOO: [APP-ACTIONS.md](APP-ACTIONS.md).

## 10. Пользовательские правила банковских SMS

Вместо глобальных шаблонов на 30–50 банков Walter обучается на примерах пользователя.

Скажи, например: «смотри это SMS от Alfa-Bank: … Сумма после «Покупка», остаток после «Баланс», категория «такси и транспорт», карта после «··». Запомни».

Walter вызовет `finance_learn` и сохранит правило с якорями:

```json
{
  "sender": "Alfa-Bank",
  "sample": "Покупка 83 RUB Баланс 561 169,43 RUB Московский транспорт ··2017",
  "signature": "Покупка",
  "operation": "purchase",
  "amount": {"after": "Покупка ", "before": " RUB"},
  "balance": {"after": "Баланс ", "before": " RUB"},
  "category": "такси и транспорт",
  "card": {"after": "··"}
}
```

- `after` — текст перед значением;
- `before` — текст после значения;
- фиксированное `category`/`value` — просто нужная категория;
- `signature` — обязательная подстрока формата SMS.

Правило сразу проверяется на исходном примере. Затем `read_sms` сначала применяет пользовательские правила, а остальной анализ остаётся на модели.

Управление: `finance_rules` — список, `delete <id>` — удалить правило, `reset` — удалить все.

## 11. Почта и сознательный отказ от Gmail OAuth/Pub/Sub

Для чтения почты используется **IMAP + пароль приложения**, для событий Gmail — обычные системные уведомления через NotificationListenerService.

Мы сознательно отказались от Gmail OAuth и Gmail `users.watch` через Pub/Sub и Cloud Run: такая настройка слишком сложна для целевой аудитории. Пользователю не нужны Google Cloud, OAuth Client ID или собственный bridge.
